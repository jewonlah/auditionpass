## 0. 북극성 재정의

**지원 가능 액션 보유 활성 공고 수** (이메일 + 폼 + 공식 접수 URL + 명확한 연락 지원). 이메일 보유율은 보조 지표.
- 현재: 활성 4,484 · 이메일 97(2.2%)
- 8주 기본 목표: **활성 5,200~5,600 · 이메일 800~1,050 · 지원 액션 보유 1,500~2,200(28~40%)** · 일일 검수 45~65건
- 실패 시 의심 가정: ① 카페 본문 접근률 과대평가 ② 카페 원문 이메일 포함률 과대평가 ③ 중복/저품질 과소평가

## 1. 확장의 전제 — P1 2개 (이것 없이 소스 늘리면 무너짐)

1. **크로스소스 dedup**: `canonical_posts`/`post_sources`/`review_queue`. 블로킹 키(이메일·전화·폼URL 해시, 마감, 기관명) + 제목 3-gram/rapidfuzz 유사도. 점수 75+ 자동 병합, 50~74 검수 후보. 원출처 우선순위: 공식 페이지 > 대학/기관 > 카페 원글 > 블로그 재게시 > 뉴스레터 > 제보. first_seen과 canonical_source 분리.
2. **auto-triage 5단계**: discard / merge / auto_publish / pending / quarantine — pending 진입률 50% 이하 목표. 자동 게재 조건: 출처 A티어 + 마감·지원방법 confidence ≥0.85 + 분류 ≥0.90 + 위험 신호 0 + dedup 완료. 신규 소스 첫 10건 자동 게재 금지. 검수 현실선 40~70건/일 — 초과 시 소스 추가 중지.

+ 소스 티어 A(자동 게재)/B(pending)/C(발견만)/D(휴면)/X(금지), 승인율 기반 자동 승격·강등(20건 85%→B, 50건 90%→A, 30일마다 재표본).

- **S3 운영화**: source_state·4큐(16h)+catch-up(8h)+블로그 RSS 20개(7h)+이메일 쿼리 20개(5h) — 판정: due job 기반 실행, 304/중복 fetch 생략, 재시작 후 회수
- **S4 확장·안전장치**: 대학·공공 게시판(12h)+뉴스레터(7h)+PDF/HWP/OCR(8h)+대시보드(10h)+제보 최소판(3h) — 판정: 소스 +40, 아침 3분 대시보드, parser_suspect 경보 작동

## 4. 필드 추출기 스펙 (공고당 정보량 확대)

- 방식: 줄 단위 후보 → ±1~2줄 문맥 윈도우 → 지급/징수/조건 분류 → 필드별 confidence.
- **페이 vs 참가비**: 지급(출연료·페이·지급 +3~2) vs 징수(참가비·등록비·수강료·프로필 촬영비·입금 +4~2) 점수 — 징수 ≥4는 페이가 아니라 `risk_fee_required`. "참가비 없음"은 안전 근거로 저장.
- 대상: 나이(20대 중반=24~27), 년생(93~97=1993~97, 03~07=2003~07 — 경계는 0~26세 휴리스틱), 키(165 이상, cm 문맥 필수), 인원(스태프 제외).
- 일정 분리: application_deadline / audition_date / shooting_dates / performance_dates.
- 신뢰도 UI: ≥0.75 표시 / 0.50~0.74 "원문 확인"+근거 스니펫 / <0.50 빈칸. **"페이 미기재"≠"무급"** 구분. 위험 신호는 저신뢰여도 노출.
- 검증: 소스별 층화 300~500건 라벨링(CSV), 목표 — 이메일·전화·폼 precision 0.98 / 위험 신호 recall 0.90 / 페이 precision 0.90 / 나이·키 0.85. 100건 단위 회귀 루프.

## 5. 남은 리스크 (10라운드 최종 지적)

1. 카페 접근 안정성 — 파일럿 실측 전 backfill 기대치 잠금 (**과대평가 주의 레버**).
2. 개인정보 보관 경계 — 전화·카톡ID 마스킹/해시·보관 기간·삭제 대응 기준 필요(36 §5와 연결).
3. 자동 게재 책임선 — A티어도 위험 신호 0일 때만.
4. 품질 KPI 보강 — 클릭률·저장률·신고율·마감 후 잔존률 병행 추적.
5. **과소평가 주의 레버 = dedup+triage** — 직접 공고를 늘리진 않지만 모든 레버의 실효 수율을 결정.
