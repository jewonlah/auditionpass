# 자동 프로필 3단계 — PDF와 사진 크롭

2026-09-11. 로컬 구현. 운영 DB 적용·배포·실제 지원 메일 발송은 수행하지 않았다.

## 구현

- 저장한 프로필과 지원 확인 화면에서 실제 제출 PDF 미리보기·다운로드.
- 사진과 한글 글꼴을 PDF 내부에 포함. 캐스팅·사진 중심·경력 중심 스타일, 긴 경력의 페이지 나눔, 클릭 가능한 포트폴리오 링크.
- 버전별 최초 PDF를 비공개 Storage에 저장하고 이후에는 같은 바이트를 반환. 동시에 생성해도 덮어쓰지 않고 먼저 저장된 파일을 사용.
- 지원 메일에 해당 PDF 첨부. 첨부 파일을 포함한 발송 요청 전체를 저장하므로 재시도에서도 같은 파일을 사용. PDF 생성·보관 실패 시 지원 발송을 진행하지 않음.
- 사진 업로드 전 3:4 크롭, 좌우·상하 위치 조절, 원본 비율 유지 선택. 작은 사진 해상도 안내.
- 서버에서 실제 이미지 디코딩·EXIF 방향 보정·크롭·최대 크기 제한·JPEG 압축. 기기에 있는 원본 파일은 수정하지 않음.
- 추가 사진은 2열로 배치하고 홀수 마지막 사진은 한 행을 사용. 미리보기에서 임의로 추가 크롭하지 않음.
- 탈퇴 시 PDF 버킷도 사진과 함께 먼저 정리. 대량 파일은 일부만 지우고 계정을 삭제하는 대신 재시도 안내.

## 경계와 제한

- 크롭은 새 업로드 단계에서 적용한다. 저장된 사진의 크롭을 다시 바꾸려면 원본을 재업로드한다.
- 사진 자체를 생성하거나 얼굴·체형을 바꾸는 기능은 없다. 자동 배치는 사진 수를 기준으로 한다.
- PDF와 웹의 페이지 비율·배치는 다를 수 있다. `제출 PDF 미리보기`가 실제 첨부되는 파일이다.
- 생성된 PDF의 사진은 URL 만료에 영향을 받지 않는다. 아직 PDF를 만들지 않은 버전의 사진 파일이 삭제되면 생성할 수 없다.
- 외부 URL을 서버에서 임의 다운로드하지 않는다. 본인 계정의 현재 Supabase 프로필 버킷에서 올린 사진만 PDF에 포함한다. 외부·과거 호스트 사진은 재업로드가 필요하다.
- 현재 PDF 3MB, 원본 업로드 5MB·디코딩 4천만 픽셀 제한. 사진은 PDF용으로 별도 압축한다.
- 폰트가 지원하지 않는 특수문자·이모지는 별도 대체 처리가 남아 있다.

## 운영 반영

1. 026 다음에 `027_profile_pdf_storage.sql` 적용. 두 migration 디렉터리의 파일은 같은 내용이므로 한 경로로 적용한다.
2. 비공개 `profile-documents` 버킷과 서버 전용 정책을 확인한다. 기존 광범위한 사용자 Storage 정책에도 이 버킷은 제한 정책이 우선한다.
3. 서버 전용 권한으로 버전별 `{userId}/{versionId}.pdf`를 관리한다. 다운로드 API는 먼저 로그인과 본인 버전을 확인한다.
4. Next 배포에는 `assets/fonts/NanumGothic-Regular.ttf`가 포함돼야 한다. output tracing 설정에 명시했다.
   Sharp는 Next 16.2.1과 같은 `0.34.5`로 고정했다. 0.35.x와 두 버전이 함께 로드되면 Windows 빌드에서 기존 OG 이미지 생성이 실패해 통일했다. Next 업그레이드 때 함께 확인한다.
5. 검증 환경에서 저장본 PDF 생성, 두 번째 조회의 동일 파일, 지정 테스트 수신자의 PDF 첨부 수신, 탈퇴 시 파일 삭제를 확인한 뒤 운영 반영한다.

PDF 처리 참고: [PDFKit 텍스트·글꼴](https://pdfkit.org/docs/text.html), [이미지 포함](https://pdfkit.org/docs/images.html). 글꼴의 출처·라이선스·해시는 `frontend/assets/fonts/README.md`에 기록했다.

## 검증 결과

- 전체 테스트 122개 통과. PDF.js로 세 템플릿의 한글·사진 5장·마지막 경력·링크·페이지 경계를 검증하고 첫 페이지 PNG를 확인했다. 사진 없는 PDF 1페이지도 검증.
- PDF 저장본의 동일 바이트 반환, 타인 버전 거부, 동시 생성 시 저장된 파일 우선, 첨부 포함 발송 요청 재시도 동일성 검증.
- 브라우저 6개 통과. 모의 Storage를 사용하되 PDF 생성과 이미지 크롭은 실제 서버 코드를 실행. 1200×800 사진을 600×800으로 자르고, PDF 첫 생성 후 재조회가 같은 파일인지 확인.
- 임시 PostgreSQL에서 026 회귀와 027 정책 검증 통과. 광범위한 기존 정책이 있어도 일반 사용자는 PDF를 조회·업로드할 수 없고 service role만 접근 가능.
- lint 오류 0, 기존 MY 이미지 경고 1. 공백 검사 통과.
- 브라우저에서는 개발 모드 재마운트 시 크롭 사진 URL이 취소되는 문제를 수정했다. PDF 검증에서는 푸터로 인한 빈 페이지와 긴 경력의 제목 분리 문제를 수정했다.
- 운영 Supabase Storage·실메일 첨부 수신·운영 탈퇴 흐름은 검증하지 않았다.
