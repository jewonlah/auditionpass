# 파일 생성과 탈퇴의 동시 실행 처리

2026-09-12. 병렬 검토에서 발견한 PDF 재생성 경합을 보완한다.

## 문제와 변경

기존에는 PDF 요청이 사진을 읽고 렌더하는 사이 다른 요청이 탈퇴를 완료하면, PDF 요청이 service role로 파일을 뒤늦게 저장할 수 있었다. 업로드 직전 계정 조회만 추가해도 조회와 업로드 사이 경합이 남는다.

028은 계정별 파일 작업 상태와 작업 토큰을 저장한다. 작업 시작과 탈퇴 시작 RPC가 같은 상태 행을 잠근다. PDF 조회·생성과 사진 업로드는 작업 토큰을 확보한 뒤 진행한다. 탈퇴는 삭제 상태를 고정하고 활성 토큰이 있으면 파일 삭제 전에 409로 중단한다. 이후 신규 파일 작업은 거절하고, 기존 작업이 끝나면 탈퇴를 재시도한다.

- `account_file_lifecycle`: 사용자 UUID와 삭제 상태. auth 삭제와 함께 지우지 않아 늦게 도착한 요청도 거절한다.
- `account_file_operations`: 작업 UUID, 사용자 UUID, 시작 시각. 개인정보 본문·사진·PDF는 넣지 않는다.
- 세 RPC와 테이블은 service role 전용이다. 클라이언트의 직접 호출·조회 권한이 없다.
- 렌더 실패처럼 업로드 시작 전 끝난 요청은 토큰을 해제한다.
- 성공한 업로드와 PDF의 명확한 409 충돌 응답은 원격 쓰기가 끝난 것으로 처리한다.
- 업로드 결과를 알 수 없거나 토큰 해제에 실패하면 토큰을 유지한다. 시간이 지났다는 이유만으로 자동 해제하지 않는다.

## 중단된 작업 복구

파일 작업 로그의 `operationId`로 정확한 작업을 찾는다. 토큰에는 파일 경로가 없으므로 사용자 경로와 해당 요청의 실행 기록을 함께 대조해야 한다. 로그에 PDF·사진 본문을 추가하지 않는다.

1. 해당 서버 요청과 원격 Storage 쓰기가 종료됐는지 확인한다. 경과 시간만으로 종료를 추정하지 않는다.
2. 해당 사용자 경로의 파일을 Storage API로 대조한다. 실행이 계속될 수 있거나 쓰기 결과가 불명확하면 토큰을 유지한다.
3. 원격 쓰기가 더 이상 발생하지 않음을 확인한 작업만, 서버 권한의 `finish_account_file_operation(p_user_id, p_operation_id)`로 해제한다. 일괄 삭제나 TTL 정리는 하지 않는다.
4. 삭제 상태를 되돌리지 않고 탈퇴를 다시 시도하여 Storage → 앱 데이터 → auth 순서로 정리한다.

일반 사용자는 계속 실패할 때 고객센터로 문의할 수 있다. 자동 복구·운영자 화면은 이번 변경에 포함하지 않는다. 토큰이 남으면 탈퇴가 완료되지 않는 것이 의도된 실패 처리이며, 이를 운영에서 대조할 담당자가 필요하다.

## 사진 보존과 범위

이전 사진 DELETE API는 인증된 요청에도 409를 반환하며 물리 삭제하지 않는다. 편집 화면에서 사진을 제외하고 저장하는 현재 흐름은 유지된다. 저장 버전 참조 여부와 파일 수명을 통합 관리하기 전까지 미사용 업로드의 개별 삭제는 제공하지 않는다. 계정 탈퇴는 모든 파일을 정리한다.

사진 URL 저장은 PDF와 같은 `ownedPhotoPath` 검증을 사용한다. 현재 프로젝트의 본인 업로드 경로만 허용하고 외부·타인·지원하지 않는 경로는 재업로드를 안내한다. 사진 필드를 제출하지 않는 부분 수정은 기존 값을 보존한다. 기존 외부 사진이 자동 변환되는 것은 아니다.

경합 보장은 새 서버의 PDF·사진 업로드·탈퇴 경로에 적용된다. 기존 클라이언트의 Storage 직접 쓰기 권한, 관리자 Storage 직접 조작, 구 배포 인스턴스까지 잠그는 변경은 아니다. 운영 반영 시 구 요청 종료와 Storage 정책을 별도 확인해야 한다. 이 변경을 전체 Storage 접근의 불변성 보장으로 해석하지 않는다.

## 검증

- 단위 테스트: 작업 중 탈퇴 차단, 삭제 요청 뒤 신규 작업 거절, 정상 작업 완료 후 재시도, 불명확한 업로드 토큰 보존, 렌더 실패 해제, RPC 실패 시 삭제 거절.
- SQL fixture: 활성 토큰 처리, 타인 토큰 해제 거절, 삭제 상태 보존, auth 사용자 존재, 클라이언트 권한 차단, 별도 DB 연결의 삭제/생성 행 잠금.
- 실제 운영 Storage·운영 탈퇴는 검증하지 않았다. 최종 로컬 실행 결과는 [운영 반영 준비](46_release-preparation-2026-09-11.md)에 기록한다.
