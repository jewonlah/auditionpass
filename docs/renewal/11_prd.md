## 1. 개요

### 1.1 문제 정의
- "사용하기 복잡하다"의 실체는 화면 수가 아니라 **여정 단절**이다. returnTo 부재로 유저가 컨텍스트를 반복 상실하고(02 §1), 첫 지원까지 최대 15단계가 걸리며(02 저니 A), 핵심 가치인 지원 추적은 2뎁스에 매몰돼 있다(02 B8).
- 디자인은 "AI SaaS 템플릿"의 전형(03 §1, AI-slop 18건), 카피는 열망 없는 기능 나열(03 §2), SEO는 sitemap 동결로 색인 파이프라인 절반이 끊긴 상태(03 §3-2)다.

### 1.2 리뉴얼 목표 (D1~D7 요약)
1. 여정 단절 제거 — returnTo 전면 도입, 인라인 게이트, 앱형 5탭 IA (D5)
2. 브랜드 재정의 — 「캐스팅 콜 시트」 에디토리얼(랜딩) + 「콜시트 유틸리티」 미니멀(앱), AI-slop 전면 제거 (D6)
3. 수익모델 전환 반영 — 지원 제한 폐지, 데드엔드 CTA 제거 (D2)
4. SEO 색인 회복 — sitemap 버그 수정 최우선, 상세 SSR·스키마 보강 (D7)

### 1.3 릴리즈 범위
- **Phase R1 (본 PRD의 중심)**: UX/디자인 전면 리뉴얼 — 아래 §3 기능 영역 1~11 전체.
- **Phase R2 (개요만, §4)**: 컴프카드 PDF 자동 생성(D1-3), 지원자 보드 읽기 전용 웹뷰(D3).

### 1.4 Non-goals (D8 — 이번 리뉴얼 제외)
- 토스페이먼츠 결제 실연동 (과금 UI/플랜 페이지 포함)
- 카카오/네이버 소셜 로그인 (사업자등록 후. **구글 OAuth만 R1 포함**)
- CD(캐스팅 디렉터) 측 풀 대시보드 (R2는 읽기 전용 보드까지만)
- 네이티브 앱 빌드 (PWA 유지)
- 크롤링 소스 확장 자체(플레이DB·기획사 페이지)는 크롤러 트랙 별도 진행 — 본 PRD는 프론트 표면만 다룸
- 인스타그램 크롤링 (D4 금지 사항)

## 2. 페르소나 & 핵심 시나리오

- **P1 지망생 (주 타겟)**: 20대 배우·모델 지망생. 밤에 폰으로 공고를 확인하고, 아침에 지원한다. "무대에 서고 싶다"는 열망이 동인.
- **P2 재방문 유저**: PWA 아이콘으로 매일 진입. 신규 공고 확인 → 지원 → 지원 현황 추적이 루틴.
- **핵심 시나리오**: 비로그인 방문 → 오디션 발견 → 지원 버튼 → (가입/미니 프로필을 그 자리에서) → 지원 완료 → 지원 탭에서 추적. **이 시나리오에서 페이지 이탈·컨텍스트 상실이 0이어야 한다.**

### F3. returnTo 시스템 (전역 리다이렉트 규칙)

**배경**
- 02 §1-1: "복잡하다"의 최상위 원인. returnTo/redirect 파라미터가 시스템 어디에도 없음 (02 §4 구조적 문제).
- 증거: 프로필 저장 → 랜딩 추방(`ProfileForm.tsx:163`, A6 🔴), 로그인 후 무조건 `/auditions`(`login/page.tsx:54`, C1 🔴), 미들웨어 게이트 목적지 상실(`middleware.ts`), 커뮤니티 좋아요/댓글 게이트(`community/[id]/page.tsx:88-91,109-112`).

**유저 스토리**
- 유저로서, 로그인이나 프로필 작성 때문에 잠시 다른 화면에 갔다 와도 **하려던 일이 있던 자리**로 정확히 돌아가고 싶다.

**요구사항**
- MUST: 전역 규칙 — 인증/프로필/글쓰기 등 모든 게이트는 진입 시 `?returnTo=<현재 경로+쿼리>`를 부착하고, 완료 시 해당 경로로 복귀한다.
- MUST: 적용 지점 — ① `middleware.ts` 서버 게이트 ② `/login`·`/signup` 성공 시 ③ 이메일 인증 콜백(`auth/callback/route.ts:35`) ④ 구글 OAuth 콜백 ⑤ 프로필 저장(`ProfileForm.tsx:163`) ⑥ 커뮤니티 좋아요·댓글·글쓰기 게이트.
- MUST: 폴백 — returnTo 부재/만료 시 로그인 유저는 `/home`, 온보딩 미완 신규는 `/onboarding`, 로그아웃 후에는 `/`(랜딩). **폴백으로 `/auditions`는 쓰지 않는다** — 기본 착지점은 홈 하나 (12_ia-userflows §6.3).
- MUST: 보안 — returnTo는 **동일 오리진 상대 경로만 허용**(`/`로 시작, `//`·절대 URL 거부). 오픈 리다이렉트 차단.
- SHOULD: OAuth처럼 쿼리 유실 가능 구간은 세션 스토리지(또는 쿠키) 백업 1회용 저장.
- MUST: 클라이언트 게이트 중복(`useAuth` 후 push) 정리 — 서버 미들웨어로 일원화하고 클라이언트는 시트 유도만 (02 §2 인증 게이트 이중화).

**수용 기준**
- [ ] 오디션 상세 → 지원 → (로그인 → 프로필) → 완료 후 **같은 오디션 상세**로 복귀한다
- [ ] 커뮤니티 글에서 좋아요 → 로그인 → 읽던 글로 복귀, 스크롤 위치 기억은 SHOULD
- [ ] `?returnTo=https://evil.com` / `//evil.com` 입력 시 폴백 경로로 이동한다
- [ ] returnTo 없이 로그인하면 `/home` 착지
- [ ] 프로필 저장 후 랜딩(`/`)으로 이동하는 경로가 코드에 존재하지 않는다

**기술 노트**
- 공용 유틸 `lib/return-to.ts`(생성·검증·소비) 신설. `middleware.ts` 게이트에서 `redirect(/login?returnTo=…)`, `login/page.tsx:54`·`ProfileForm.tsx:163`·`community/write/page.tsx:35-38` 소비부 교체.
- 구글 OAuth는 Supabase `signInWithOAuth`의 `redirectTo` 옵션에 콜백+returnTo 인코딩.
