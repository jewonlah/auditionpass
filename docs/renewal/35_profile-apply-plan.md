## A. 소셜 로그인 로드맵 (OAuth 4종)

전부 Supabase Auth 프로바이더로 지원되므로 코드 구조는 동일하고, **병목은 각 사의 심사·자격 요건**이다.

| 프로바이더 | 자격 요건 | 시점 | 비고 |
|---|---|---|---|
| 구글 | 없음 (현행) | ✅ 지금 | 웹·안드로이드 주 로그인 |
| 이메일 | 없음 (현행) | ✅ 지금 | 보조 |
| 카카오 | **사업자등록번호 필요**(비즈 앱 전환 — 동의항목·검수) | 사업자등록 후 | 국내 전환율 최고 예상. 현재 보류 사유가 이것 하나 |
| 네이버 | 앱 등록 + 검수(서비스 URL·개인정보 처리방침 URL 필요) | 사업자등록과 같은 시기에 일괄 | 개인도 신청 가능하나 검수 통과를 위해 처리방침 페이지 선행 |
| 애플 | Apple Developer Program($99/년) | **iOS 앱 출시 시점에 필수** | 앱스토어 심사 지침 4.8 — 타사 소셜 로그인을 제공하는 앱은 Sign in with Apple 의무 |

**실행 순서**: ① 지금 = 구글+이메일 유지 ② 사업자등록 완료 → 카카오·네이버 동시 신청(개인정보 처리방침 페이지가 심사 요건이므로 §C 방침 화면 먼저 배포) ③ iOS 앱 빌드 시점 → 애플 추가. 계정 통합: 같은 이메일이면 기존 계정에 프로바이더 연결(Supabase identity linking), 충돌 시 "이미 구글로 가입된 이메일" 안내.

## B. 이메일 대리 지원 — "메일로 우선 보내는 게 최선"

### B-1. 왜 메일이 최선인가
- CD(캐스팅 담당)의 접수 창구 실측: 이메일 접수가 압도적 1위, 그다음 구글폼·오픈카톡. 오픈카톡·전화는 자동화 대상이 아님(사칭 리스크).
- 메일은 **지원자 명의로 정식 문서를 남기는 유일한 채널** — 지원 이력·열람·회신 추적이 전부 가능.

### B-2. 지원 방식 우선순위 (공고별 자동 결정)
```
apply_email 있음  → ① 원클릭 대리 발송 (초록 배지 — 핵심 상품)
구글폼 링크 추출됨 → ② 폼 열기 + 내 프로필 복사 도우미 (필드값 클립보드/자동채움 R2)
그 외             → ③ 원문 링크 + "프로필 복사" 버튼
```

### B-3. 대리 발송 메일 규격
- **발신**: apply@auditionpass.co.kr (SPF/DKIM — Resend 설정 완료) · **Reply-To: 지원자 이메일** — CD가 답장하면 지원자에게 직접 도착, 우리는 중간에 서지 않는다.
- **제목**: `[지원] {공고 제목} — {이름} ({분야}, {출생연도}년생)`
- **본문**: 공통 신청폼(§C) 필드를 공고사가 익숙한 순서로: 이름 → 출생연도(나이) → 성별 → 키·몸무게 → 거주지역 → 연락처 → 경력 요약 → 자기소개 → 영상 링크 → SNS. 공고가 양식을 지정한 경우(실측 39건 "아래 양식대로") R2에서 양식 파서로 필드 재배열.
- **첨부**: 컴프카드 PDF 1장(프로필 사진 2 + 핵심 스펙) + 원본 사진 2장. 총 5MB 이하로 리사이즈.
- **푸터**: "오디션패스를 통해 접수된 지원입니다 · 지원자 열람용 보드 {board 링크}" (D3 CD 유입 루프).

### B-4. 발송 플로우·안전장치
1. 지원 확인 시트(게이트 ⓒ) → **메일 미리보기**(받는 사람·본문·첨부 확인) → 발송.
2. `applications` 기록: 발송됨 → 열람됨(오픈 픽셀) → 회신(지원자 셀프 체크 R1, IMAP 연동 없음).
3. 안전장치: 같은 공고 재지원 방지(1회, 수정 재발송은 24h 1회) · 계정당 일일 발송 상한 20건 · 마감 지난 공고 발송 차단 · 수신 거부 요청 도메인 블랙리스트 · 발송 실패(반송) 시 지원자에게 알림 + 원문 링크 폴백.
4. 개인정보: 발송 시점에만 CD에게 전달, 열람 보드는 토큰 만료(90일). 처리방침 §"제3자 제공"에 명시(캔버스 Privacy 화면 반영됨).

### C-2. 3계층 필드 설계 = 프로필 구조
| 계층 | 필드 | 상태 배지 |
|---|---|---|
| **필수** (지원 가능 최소선 — 가입 마찰 최소화, 여기만 온보딩) | 이름 · 출생연도 · 성별 · 분야(14카테고리 다중) · 연락 이메일 | "지원 가능 ✓" |
| **기본 스펙** (공고 대부분이 원함 — 실측 상위 + 사용자 지시) | 전화번호 · 키·몸무게 · 활동 지역(+상경 가능 여부) · **학교·전공(재학/졸업)** · **소속사(무소속/소속명, 소속 시 매니저 연락처)** · **특기·장기 + 취미(태그 다중 + 자유 입력: 악기·무술·사투리·외국어·댄스·보컬·운동…)** · **예명·활동명(선택)** · **국적(기본 대한민국, 외국인은 체류 자격)** · 경력(작품/역할/연도 반복 행) · 자기소개 200자 · 프로필 사진 2장(얼굴+전신) | "원클릭 준비 ✓" |
| **공통 선택** (있으면 채택률↑) | 수상 경력 · 촬영 가능 일정(요일·시간대) · 자기소개 영상 링크 · 외국어 수준 · 여권 유무(해외 촬영) · 문신 여부(촬영 제약 고지) · 운전면허 · **희망 페이(협의 가능 체크)** · **거주 시·군·구(활동 지역과 별개, 이동 판단용)** · **카카오톡 아이디(카톡 접수 공고용)** | — |
| **분야별 확장** | 배우: 연기 영상·필모·사투리 가능·병역(성인 남성)·**머리 길이·염색/삭발 가능·시력** / 모델: 상의·하의·신발 사이즈, 화보 링크, 머리 정보 공유 / 가수·댄서: 퍼포먼스 영상·**레퍼토리(참가곡 후보)** / 인플루언서·광고: SNS 링크+팔로워 수 / 키즈: 보호자 이름·연락처·동의, 학년 / MC·쇼호스트: 진행 영상·방송 이력 | "컴프카드 준비됨 ✓" |

- **프로필 = 지원서**: 한 번 작성하면 모든 공고에 재사용. 발송 시 §B-3 순서로 자동 조립: 이름(예명) → 출생연도(**만 나이 자동 병기** — 실측 47건이 만 나이 요구) → 성별 → 국적 → 키·몸무게 → (의상 사이즈) → 활동 지역 → 연락처 → 학교·전공 → 소속사 → 경력 → 특기·취미 → 자기소개 → 영상·SNS 링크.
- 병역·문신·보호자 등 민감 항목은 해당 분야·조건에서만 노출(전 유저 공통 폼에 깔지 않는다).

### C-4. 공고별 추가 질문 — 프로필에 넣지 않는 것
실측에서 **지원 배역·참가곡·가능 날짜·역할 선택**("좀비/인간" 같은 작품 고유 질문)은 공고마다 다르다 → 고정 필드가 아니라 **지원 시점 입력**으로 처리:
- 메일 미리보기 화면에 "이 공고의 추가 질문" 섹션 — 공고 본문에서 양식 파서(R2)가 질문을 추출해 입력란 생성, R1은 자유 입력 1칸("담당자에게 한마디 / 지원 배역 등").
- 답변은 메일 본문 최상단(공고사가 가장 먼저 보는 위치)에 배치.
- 분야 선택에 따라 확장 섹션이 동적으로 열림(온보딩 Step1의 선택이 폼 구조를 결정).
- 민감정보(신체·사진)는 선택 입력 + 발송 시에만 전달 + 탈퇴 즉시 삭제(처리방침과 일치).
- 컴프카드 PDF: 표준+확장 채우면 자동 생성(D1). R1은 프로필 요약 텍스트, R2에 PDF.

### C-3. 프로필 작성 경험 (사용자 지시 ④)
- 온보딩 3스텝(12 문서 F1)이 **필수 계층만** 받는다 — 3분 완료.
- 홈 완성도 카드가 표준→확장을 단계 회수: "사진 1장이면 원클릭 준비 완료" 식으로 **다음 1개 행동만** 제시.
- 게이트 시트 ⓑ: 지원 순간에 부족 필드만 인라인 입력(전체 폼으로 추방 금지).
- 입력 최소화: 키·몸무게 숫자 스테퍼, 지역 시·도 선택, 경력은 "작품명/역할/연도" 3필드 반복 행.

## D. 구현 순서 제안
1. **P2 확장(프론트)**: 프로필 2섹션 → 3계층 재편 + 완성도 배지 3단계 (12 문서 P2와 병합)
2. **메일 미리보기 + 발송 규격 B-3** (Resend 템플릿 교체, Reply-To 적용 여부 확인)
3. **applications 상태칩** 발송/열람(픽셀)/회신
4. **구글폼 도우미** (②경로) — 클립보드 복사 R1
5. 사업자등록 후: 카카오·네이버 로그인 + (iOS 시점) 애플
6. R2: 지정 양식 파서 · 컴프카드 PDF · 구글폼 자동채움
