## 2. 사용자 확정 원칙 (최종 반영분)

1. **원클릭 오디션 = 메인 상시 노출** — 홈(`/home`) 최상단 섹션은 항상 "원클릭 오디션"(바로 지원 가능 공고, 초록 pill). 12 §3·11 F2에 MUST로 반영, 프로토타입(22) 홈 캐러셀 최상단 고정, 랜딩(21) 히어로 카피·Step 03·가치축 03에 "원클릭 지원" 용어 노출.
2. **앱 UI = 네이티브 감각 필수** — "웹사이트 같다" 피드백에 따라 iOS large-title 타이포, chevron-only 뒤로가기, 44px 터치 타깃, 인셋 디바이더, grabber 핸들, hover 금지(:active 프레스만), 푸터·브레드크럼 금지. 20 디자인 언어에 명문화, 22에 적용 완료.

- **일관성 검수(29)**: 문서 4종 교차 검수, 모순 **12건 수정** (미니 프로필 필드 "이름·출생연도·성별" 통일 5건, 지원 게이트 returnTo 방식 정정 2건, 열람 확인 기능의 릴리즈 단계 충돌 4건 — 인프라 R1.2/노출 R3 프리미엄, 인용 보정 1건). **D1~D8 위반 없음.**

- **프로토타입(22)**: Chrome 실측 — 콘솔 에러 0, 5탭 전환·상세 push/back·지원 시트 3종 플로우·필터·스켈레톤·reduced-motion 전부 작동 확인. 더미 공고 14건(원클릭 9건 과반).

## 4. 유의점

- **포지셔닝(D1) vs 원클릭 노출**: 10 기획서는 "원클릭은 경쟁사가 카피 가능한 기능이라 포지셔닝 축으로 쓰지 않는다"(3축 해자)고 정의. 사용자 지시는 **UI 노출 우선순위**에 대한 것으로, 마케팅 포지셔닝 문구(D1 "다음 무대" 약속)는 유지한 채 제품 화면·카피에서 원클릭을 전면 노출하는 방식으로 양립시킴.
- 랜딩·프로토타입은 시안(HTML)이며, 실제 구현은 11 PRD의 릴리즈 계획(R1.1 → R1.2 → R2 → R3)과 23 디자인 시스템 토큰을 따른다.
